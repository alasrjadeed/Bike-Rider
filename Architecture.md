# BIKE RIDER — Architecture

Single-file progressive web app: `index.html` (~6,400 lines) contains all HTML, CSS, and the entire Three.js game. `sw.js` + `manifest.webmanifest` give offline PWA behaviour.

There is **no bundler and no build step for the game itself** — edit the file and reload. Around it sits a
zero-dependency Node toolchain (`package.json`, `npm test`, `npm run build`): a static audit, a headless-Chrome
regression suite driven over the DevTools Protocol, a one-way mirror into `public/`, and an Android APK built with
the raw SDK tools. Nothing needs `npm install` because nothing has dependencies.

The **canonical** copy is the root `index.html`. `public/` is a mirror that also carries `icons/`, and
it is what gets hosted and what gets baked into the APK. `tools/sync-public.mjs` copies one way; `--check` reports
drift.

## Runtime architecture

```
 loadSave() ──► SAVE (localStorage 'bahrain_rider_save_v1')
                      │
 initMaterials() / buildTextures() / buildPrototypes()
                      │
 loop(now) ──► tick(dt)                 [fixed-ish dt, RAF, clamped]
   ├─ playerUpdate(dt)        physics + interaction + hazards/collision
   ├─ trafficUpdate(dt)       oncoming traffic (T.list/T.opp)
   ├─ crossUpdate(dt)         junction cross-traffic (X.list)
   ├─ spawnHazardEvent / hazards
   ├─ evUpdate(dt)            checkpoint / rush-hour events
   ├─ pedsUpdate(dt)          streetside pedestrians
   ├─ worldUpdate(pz)         chunked streaming world (CHUNK = 40 m)
   ├─ updateEnvironment(dt)   day/night + weather
   └─ UI.update()             HUD binding
```

Single source of truth: module-scoped globals (`SAVE`, `G`, `P`, `T`, `H`, `EV`, `W`, `M`). No DOM<->state sync library — a small `UI` object binds DOM.

## Road curvature model

- **The route is straight.** `CURVE_ON = false` (index.html) is the single switch for the whole curvature feature; the ramp `W.curveK(d)`, `W.cx(d)`, `W.cdx(d)` and `W.cy(d) = -atan(cdx(d))` are all still present and are all scaled by it, so the road is dead straight (`cx === 0`, `cy === 0`) without touching a single consumer. Flip the constant and the bend comes back.
- It is **off** because the curve fed the road and everything driving on it through two incompatible coordinate models. Geometry used a rigid per-chunk rotation; the player, traffic, hazards, camera and minimap used a plain lateral offset `x = cx(d) + lateral`. Those agree only when `y === 0`, so on a real bend every lateral placement landed in the wrong place. `W.worldX(lateral, d)` is now the one shared projection — `cx(d) + lateral*cos(cy(d))` — and the player, traffic, vehicles, hazards, camera, showroom, repeaters and minimap all go through it.
- The chunk-local frame is `(lx, lz)` with depth `d = d0 - lz`; `Chunk.warpFrame()` builds a vertex warp from that and `Chunk.pt()` inverts it, and **both must use the same `d`**. They each used to advance the distance by `lz` *as well as* `d0`, so a chunk drew 80 m of road into a 40 m slot. A chunk is placed at `z0 = -k*CHUNK` with `d0 = CHUNK/2 - z0`, which makes the span exactly `CHUNK`.
- `drawMap` projects through the same functions, so the minimap follows the road.
- `P.d` stays route distance and `P.x` stays road-relative, so no collision system ever needed a rewrite.
- Re-enabling the bend still needs one decision made explicitly: with the tangent, `P.d = -P.z` is no longer the along-road distance. The straight-mode regression (`curvature-consistency`) asserts that identity and is expected to fail the moment `CURVE_ON` goes back on — that is the signal to revisit the arc-length/depth convention, not a bug to suppress.

## Road content model

- `drawZebra()` and `drawRoadSignTex(kind)` produce real crossing and sign textures (`TEX.zebra`, `TEX.rsign`); signs are billboarded, crossings are laid on the road.
- `Chunk.addZebra/addRoadSign/addRoundabout/addBusStop` build crossings, speed/give-way/school/horn signs, roundabout islands with trees, and bus-stop zebra pairs.
- `W.planOf` reserves chunks for `petrol` / `inter` / `round` / `school` features; `W.rounds`, `W.schools` and `W.crossings` are the queryable registries.
- `Chunk.add()` re-parents pooled props with a plain `g.add()`. It used to use `Object3D.attach()`, which preserves an object's *world* transform across a re-parent by overwriting its local one through `Matrix4.decompose` — and it ran *after* `place()` had set the transform, so it silently substituted the frame of whichever chunk the prop was recycled from. Pooled buildings came back mirrored 180 deg across the carriageway. The chunk group sits at identity, so local and world coincide and a plain `add()` is correct. `place()` writes all three Euler axes and `poolGet()` resets a recycled prop, so no stale transform can survive a reuse.
- `fillSide()` works in chunk-local Z. `placeClear(key, side, lx, ...)` takes a **signed** lateral: its "face nearest the centreline" is derived from the sign of `side`, so passing a magnitude for a negative side silently reads the far face and places the prop across the road.
- `ENV.lands` cycles four Bahrain silhouettes (Qal'at al-Bahrain fort, refinery flare stack, corniche towers, high-rise cluster) every 900 m around the player's position.
- Traffic treats a vehicle inside a roundabout ring as `v.inRound` and caps it at 5.5 m/s so it circulates instead of cutting through.

## Offline and the service worker

- `sw.js` is **network-first with a cache fallback**. Online, every response is passed straight through and also
  written to the cache; the cache is only consulted once the network has already failed. That ordering is the
  whole point: a worker that served cache-first would show players a stale game indefinitely.
- `registerServiceWorker()` in `index.html` is the only thing that installs it, and it is deliberately unable to
  break boot — it no-ops without `serviceWorker` support or on `file://`, and swallows the registration promise.
  It checks `document.readyState` before choosing between registering now and waiting for `load`, because `init()`
  is async and `load` has usually already fired by then.
- The precache (`CORE` in `sw.js`) covers the shell, the manifest, the icons and the vendored Three.js. The
  webfonts are fetched from Google, and the worker deliberately ignores cross-origin requests, so offline the UI
  uses its own fallback stack. On Android that stack resolves to system Noto faces, including Naskh Arabic, so
  Arabic renders rather than turning into boxes.
- The Android shell serves the build from `assets/public/` over `https://appassets.androidplatform.net/` and
  blocks every other host. That host choice is not cosmetic: `file://` makes localStorage unreliable and gives
  the worker an opaque origin, so the save system and offline caching both need a real secure origin. Because
  assets are local and foreign hosts are blocked, the installed APK is offline by construction.
- **Consequence for WORLD RIDERS:** the Android shell declares no `INTERNET` permission and refuses off-host
  requests, so the global board is **unreachable in the packaged app** — by design, not by bug. `SB.packaged()`
  detects the shell host and the board screen says so instead of pretending to be offline. The board is a
  **web build** feature. Enabling it in the APK would mean adding `INTERNET` to the manifest and allowing the
  Supabase host through `shouldInterceptRequest` — a real change to the app's privacy posture, so it stays off
  unless that is an explicit decision.
- `tools/regress.mjs` `offline-boot` proves the web path: it stands up a second server, lets the worker install,
  **shuts the server down**, and reloads. Nothing can be fetched but out of the cache. It runs in its own browser
  target because the shared session is driving a live game the other groups depend on.

## Landmarks

- `LMARKS` maps every district id to a monument kind, English name and Arabic name: 48 for `bh`, 20 each for
  `sa`/`ae`; `LMSIDE` picks which side of the road each one sits on so the building strip can be skipped there.
- `lmModel(kind)` bakes one `MB` geometry per kind — 30 kinds across all chapters (bh uses 18 of them,
  ≈19.7k triangles for that subset), built once at load; `lmRegister()` publishes them as
  `POOL.make['lm_'+kind]`, so landmarks are pooled like every other prop.
- `W.planOf(k)` adds at most one landmark per district to `W.lmarks` (guarded by `W.lmSeen`); `Chunk.setup(k)`
  looks up `W.lmarks.find(L => L.k === this.k)` and places it with `Chunk.place()`, which warps the offset
  through the chunk's own frame — that is why landmarks sit correctly on curved road instead of off in the void.
  The model is turned `±π/2` so its facade faces the carriageway.
- Riding within 150 m of an unseen landmark toasts it, sets `SAVE.seen['lm:<id>']`, bumps `SAVE.lmCount` and
  pings a save. The shift summary renders `LANDMARKS n/48`.

## Chapters (multi-country)

One engine, three runtime-swappable country chapters. Only the swappable surfaces live in data; geometry
builders and building mixes are shared.

- `CHAPTERS` (declared right after `padCityInvariants`) holds three self-contained profiles: `bh` (Bahrain),
  `sa` (Saudi Arabia — one city, **Riyadh**), `ae` (UAE — one city, **Dubai**). Each carries `districts`, `lmarks`, `lmside`, `streets`, `busRoutes`,
  `cityPools` (`generic` / `malls` / `real` regex), `theme`, `currency`, `plate` and a `trafficScale` map.
- **The live world arrays are mutated, never re-assigned.** `CHAPTER.swap(c)` clears `BAHRAIN` in place and
  pushes the chapter's districts (`length=0` + `push`), so every reader of the `BAHRAIN` global — `districtAt`,
  `pushSeg`, `randomDistrict`, `padCityInvariants` — keeps working unchanged. `LMARKS`, `LMSIDE`, `STREETS`,
  `BUSROUTES` and `fmtRs` are `let` bindings that are reassigned to the chapter's arrays/formatter.
- **`bh` can never drift.** `CHAPTER.bind()` snapshots the game's original arrays (`BAHRAIN.slice()`,
  `Object.assign({}, LMARKS)`, …) into the `bh` chapter at boot *before* any swap mutates the live globals —
  because `bh.districts` shares the same district objects, padding is idempotent and the round-trip restores
  the exact 48-district catalogue the regressions pin.
- **Swap order** (`CHAPTER.set(id)` → `activate(c, rebuild=true)`): `SAVE.chapter=id` + `persist()` →
  swap arrays → `padCityInvariants()` → `applyTheme()` (CSS `--bh`/`--bhAcc` + `meta theme-color`) →
  `lmRegister()` (landmark pools for the chapter's kinds) → `rebuildPlate()` (plate canvas) →
  `trafficClear()` + `T.pool={}` (pooled vehicles die with their livery) → `buildTrafficProtos()` (bus colour +
  route blinds) → `worldReset()` + `playerReset()` + `rebuildBike()` → toast + re-render of the country tabs,
  profile row, settings row. `boot` calls `activate(c, false)` (no rebuild — the world isn't built yet).
- `plateCanvas()`/`rebuildPlate()` draw the licence plate from `CHAPTER.active.plate` (country band, stripe,
  suffix, colours); `MAT.plate`'s `.map` is swapped in place, so every bike's plate follows the country without
  a bike rebuild. Bus livery reads `CHAPTER.active.theme.busColor` in `buildTrafficProtos`.
- `spawnAhead` multiplies the district traffic mix by `trafficScale` when a chapter defines one (skewed toward
  cars on sa/ae so `weighted()` stays all-positive).
- `SAVE.chapter` is a top-level save field (`'bh'` default); `deepMerge` migrates old saves, export/import
  carries it, and unknown ids fall back to `bh`. `CHAPTER.init()` runs from `boot` after `migrateSettings()` and
  before `padCityInvariants()`/`buildTextures()`.

## Rider progression (two layers)

- **Trained skills** — `SKILLS` (6 perks × 3 ranks) bought with `SAVE.sp`, one point granted per rider level
  earned through the real payout path. `skLvl(id)` reads the rank; `applySkills()` runs at the end of
  `computeStats()` and writes into `P.stats`, so nothing else in the game needs to know skills exist:
  `st.brake ×(1+0.09·rank)`, `st.horn ×(1+0.16·rank)`, `st.grip ×(1+0.11·rank)`, `st.fuelUse ×(1−0.07·rank)`,
  plus `SK.shake` / `SK.hole` for camera and pothole punishment. Money uses `skPayMult()`, applied to **both**
  the fare quote and the payout so the two can never disagree.
- **Level perks** — `PERKS` (LV2–LV5: smooth braking, lane filtering, night vision, rain grip) are *derived*
  from `levelOf(SAVE.xp)` by `perkOn(id)` rather than stored. A derived flag cannot desync from the level and
  needs no save migration; the resolved multipliers live in `SKPERK` for the systems that read them
  (collision box in `playerInteractions`, wet factor in `playerUpdate`, headlight throw in `buildPlayerBike`).
- The SKILLS garage tab lists both layers: earned perks first (inert rows, `garageAction` refuses them),
  then trained rows with pips. `garageAction('skill', id)` blocks overspend and over-cap.

## Rules and traffic AI

- School zones (`W.schools`, `W.schoolAt(d)`, `schoolUpdate(dt)`) cap speed at 30 km/h with a 2.4 s grace and fine BHD 10; `hornDown` refuses the horn inside a zone (BHD 5) and plays a short beep instead. Signs, fences and a HUD hint make the rule readable.
- Pedestrians (`PED_KINDS`, `pedSpawn`, `pedsUpdate`) wear six clothing variants plus backpacks, hi-vis vests, caps and hard hats. A mode machine — `walk → toCross → waitCross → cross → toBus → waitBus` — sends them to the nearest crossing (`W.crossings`) or bus stop, holds them at the kerb, and resumes when the way is clear.

## World streaming model

- Player moves along −Z. `worldUpdate(pz)` keeps a ~chunked window around the player.
- `LANES = [-4.2, -1.4, 1.4, 4.2]`, road half-width 5.6 m (9.5 m on a highway carriageway).
- **Rider model is `(P.d, P.x)`.** `P.d` is the route distance the whole world is built around
  (`P.z = -P.d`), `P.x` is road-relative, and `P.wx = P.x + W.cx(P.d)` is the world position. The rider
  also holds `P.yaw` — a heading **relative to the road tangent**, capped at `YAW_MAX` (0.5 rad) — so
  `P.d += speed·cos(yaw)·dt`, `P.x += speed·sin(yaw)·dt` and the drawn rig is
  `W.cy(P.d) + P.yaw`. Keeping the tangent-relative heading is what lets traffic, pedestrians, crossings,
  fuel, jobs and the camera keep working on a curved road.
- **Speed belongs to the player.** `P.cruise` is the held speed: the throttle raises it toward
  `st.top × surface`, the brake lowers it, and letting go coasts. `W.rideLimit(lay)` and
  `W.asphaltHalf(lay)` give the per-layout kerb and tarmac edge; scraping the kerb scrubs speed and
  straightens the front wheel. `P.offRoad` reuses the existing rough-surface wear/dust path.
- Junction turns (`TURN`) temporarily own `P.yaw` and hand it back as 0 when the turn ends.
- Buildings/street furniture pulled from prototype pools (`BPROTO`), keyed per district style, placed by chunk, recycled by `poolPut` when behind the camera — no per-frame allocation, no memory growth.

## Road clearance

Three numbers describe the road's width, and they are deliberately separate. `W.asphaltHalf(lay)`
is the tarmac edge, `W.kerb(lay, side)` is the outer edge of the footway (where a building has to
begin), and `W.rideLimit(lay)` is the player's own clamp. `W.kerbClearsRider(lay)` asserts the
third never exceeds the second on any layout or side, so the player physically cannot reach a wall.

Nothing hard-codes an offset any more. Every model measures its own footprint on first build
(`measureExtent`, wrapped around each factory by `selfMeasuring`, cached in `EXTENT` and rotated
analytically by `extentAt`), and each is placed through one of two gates:

- `classOf(key)` sorts models into `surface` (markings, unconstrained), `over` (kerb furniture —
  lamps, trees, signs, bus stops, fences; may overhang the rideable width but must not stand on the
  tarmac) and `solid` (buildings, landmarks, structures; must clear the kerb line).
- `clearX(key, side, lay, yaw, sx, sz)` returns the correct offset, and `placeClear(...)` is the
  same function as a development tripwire: it accepts an offset, checks the invariant that the
  model's face nearest the road is at least the boundary from the centreline, and corrects it while
  reporting under `?clearance=1`. Call sites keep their own intent and the gate only ever fixes.

`SPAN` is the allow-list of deliberate overhangs — currently just the Manama gate arch, which
`clearX` centres on the road and which the landmark rule never yaws. A span is exempt from the
clearance gate, so its width is its own obligation: it must be at least as wide as the widest
`rideLimit`, or a player in an outer lane would ride *beside* the arch rather than under it. The
`road-clearance` regression group asserts all of this across every model, layout, side and yaw
rather than leaving it to a screenshot.

## Object pooling

Universal pattern: `poolGet(key)` / `poolPut(o)` and dedicated pools (`RIGPOOL`, vehicle pools per prototype, hazard pool). Everything is **created once, recycled forever** to keep GC pauses off the mobile render thread.

## Rendering highlights

- Vertex-coloured baked geometry (`MB`) → 1 draw call per static object, skips material/texture baking for most objects.
- Canvas-generated `THREE.CanvasTexture` for roads, signs, billboards, branded gantries, brand strips.
- Single merged "world" material set (`MAT.world`/`MAT.lit`) + glow sprites for lamps.
- Night: emissive windows/lights scaled by `applyTOD`; headlight with `applyLitLevel`; fog/dust in smog, wet shader-ish darkening in rain.
- Quality: `auto`/`low`/`high` (`applyQuality`) — low cuts prototype counts + aniso.

## Audio architecture

`AU` wraps `AudioContext` (created on first user gesture). **Every sound is synthesised** — oscillators, noise and
filters, no audio files anywhere in the project. Engine pitch follows RPM; horn is a synth burst
(`hornDown`/`hornUp`); volumes obey settings (`sound`, `music`, `sfx`).

Two platform notes: the audio graph will not start until a user gesture, so the Android shell sets
`setMediaPlaybackRequiresUserGesture(false)`; and the old `public/music/` stems folder (unused
sample material) has been **deleted** — it was referenced by nothing, since every sound is synthesised.

## Save format

`localStorage['bahrain_rider_save_v1']`, schema `v:1`. Holds cash, XP, rating, jobs/shifts/distance, upgrade levels, cosmetics (+owned lists), bike, condition (fuel/engine/tyres/damage), settings (sound/music/sfx/quality/shake/time/weather) + `settings.ads` (provider ids, reward, `premium` entitlement), `credits`, `adLastClaim`, `rider.name`, `company.*`, `debt`, tutorial flag, stats (violations/perfect/failed), `seen` toasts, and the active country `chapter` (top-level, `'bh'` default). `credits` and the `premium` entitlement deliberately survive `RESET PROGRESS`. `deepMerge` forward-migrates old saves; unknown fields dropped, missing fields defaulted (so pre-chapter saves boot on `bh`). See `security.md` for save-integrity handling.

Two migrations are worth knowing about:

- **Camera shake is tri-state** (`'normal' | 'reduced' | 'false'`), read through `shakeScale()`. v1 saves stored a
  boolean, so `migrateSettings()` runs from `loadSave()` and maps `true → 'normal'`, `false → 'false'`, and
  anything unrecognised back to `'normal'`.
- **`UI.saveImport()`** (Settings → Export / Import) round-trips a save through a textarea, because `prompt()` is
  unsupported in several Android WebViews and `navigator.clipboard` is unavailable on non-secure origins. It
  refuses anything without a truthy `v` and anything with `v > 1`, and restores `settings.ads`, `credits` and
  `adLastClaim` from the live save afterwards — studio-owned fields never travel in a player save.

## Studio (owner) administration — ads & credits

Ads and credits are **owner-only**. Players have no ad or credit controls anywhere in Settings, and no way to mint credits: the only player-visible ad is the studio house ad that plays between shifts, which exists to serve the owner's ad revenue.

- `localStorage['bahrain_riders_owner_v1']` → `OWNER` (loaded by `loadOwner()`, written by `saveOwner()`). Kept in a **separate key** from the player save so `RESET PROGRESS` can never wipe studio config, passcode or ledger.
- `OWNER.ads` `{provider:'sim'|'admob'|'youtube', admobApp, admobUnit, ytVideo}`, plus `reward`, `premiumPrice`, `length`, `skipAfter`, `waitMin`, `enabled` (global kill switch), `cfgUrl`, `pass`.
- `adCfg()` merges the player save's ad block under the studio block, so **studio config always wins**. `adLength()`, `adSkipAfter()`, `adWaitMs()` read studio values; the old hard-coded `AD_WAIT_MS`/`AD_SECONDS`/`AD_SKIP_AFTER` constants are gone.
- Entry point `#screenAdmin` is **hidden**: 5 taps on the start-screen logo inside a 0.9 s window, or `?admin` / `?admin=CODE`. It is passcode-gated (default `1234`, changeable under BACKEND; the first-run hint disappears once changed). The page pauses the ride and resumes on close.
- Sections: AD NETWORK (provider, AdMob app/unit, YouTube id, length, skip-after, on/off), REWARDS & CREDITS (credits per ad, cooldown, premium price, issue +1/+5/+10/+50, take all, grant/revoke/sell premium), REVENUE LEDGER (house ads shown, reward ads shown/completed, credits issued, premium sold, credits taken, last sync, run test ads), BACKEND (remote config URL + fetch, change passcode, reset player save).
- Test ads run as `adOpen('test')` so they exercise the real render/grant path without polluting the ledger.
- `ownerBump(k,n)` maintains the ledger; `grantCredits`, `grantPremium`, `buyPremium` all record into it.
- `fetchRemoteConfig()` is the backend stub: `GET OWNER.cfgUrl` → `{ads:{…}, reward, premiumPrice, length, skipAfter, waitMin, enabled}` merged into `OWNER`, with a 5 s timeout and `lastSync` stamp. Empty URL = inert.
- Player-facing reward claims are gone by design; the owner issues credits. `adWaitLeft()` still gates the reset-progress ad.
- **SUPABASE** section: project URL, publishable key, board on/off (master switch), TEST connection, CLEAR CACHE. The key is the client-safe publishable pair; the panel warns against pasting a `service_role`/`sb_secret` key.

## WORLD RIDERS — the opt-in global board

The only network code in the game. It exists to be **deletable**: `SB` is a single self-contained module with no dependants other than the board screen, the start-screen button and one Settings row.

- **Transport:** plain `fetch` → PostgREST RPC (`/rest/v1/rpc/top_board`, `/rest/v1/rpc/submit_score`). `@supabase/supabase-js` is deliberately *not* used — vendoring it (or loading it from a CDN) would break the "no remote script dependencies" audit rule, and the whole surface is two calls.
- **Config:** `OWNER.sb {url, key, enabled}` in the studio store, not a hard-coded const, so a fork can retarget its own Supabase project from the admin panel. Default `enabled:false` — the game never calls out until the studio turns it on.
- **Consent, twice:** `SB.enabled()` requires `OWNER.sb.enabled` **and** `SAVE.settings.board` (player Settings → *Global board*). Either off ⇒ no request is ever made.
- **Read on open, write on press:** opening the board reads; the only write is the explicit **SUBMIT MY BEST** press. Nothing posts automatically.
- **Offline-safe:** every call is wrapped in a 7 s `AbortController`; failures are swallowed and the last good board (`localStorage['br_board_cache_v1']`) is shown with an "OFFLINE?" note. A dead network never throws into the game loop.
- **Identity:** `SAVE.deviceId`, a UUID generated once (`crypto.randomUUID` with a `Math.random` fallback for non-secure origins). It is a row key, not an account.
- **Untrusted names:** rows come from other players' devices, so `rider_name` is rendered through `esc()`. The audit's unescaped-`innerHTML` check covers this.
- **Server is the boundary:** the client holds the *publishable* key; RLS grants `anon` SELECT only, and all writes go through the `SECURITY DEFINER` `submit_score()`, which clamps every value. See `backend scema.md` → *Supabase* and `security.md` → *The leaderboard backend*.

`G.state` ∈ `boot → menu → garage → playing ⇄ paused → summary → menu` (the garage hosts the Service / Performance / Style / Bikes / **GAUSS AUTO** tabs), plus `modalConfirm`/`modalSettings`/`modalAd`/`screenAdmin`/**`screenBoard`** overlays. ## Performance notes

- Constantly re-used `Geometry` via `gKey`/`GEO` cache.
- Temp vectors/matrices (`_v1`, `_q1`, `_e1`, `_m3`) to avoid GC churn in `tick`.
- FPS-independent physics with clamped dt; autopilot available for testing (`autopilot()`, enabled by `?test` or
  `G.autopilot`).

## Test seams

The game is one IIFE, so the suite reaches its internals through a small set of deliberate entry points. They are
load-bearing — renaming one breaks `tools/regress.mjs`.

| Seam | Purpose |
|---|---|
| `?debug` | Exposes `window.__BR` with `ev: x => eval(x)`, the only way a test can see `G`, `W`, `SAVE`, `UI`. |
| `?test` | `G.autopilot = true`, `G.noTutorial = true`, starts a shift. Used by the soak. |
| `window.__brBack` | The game's `goBack()`. The Android hardware back button calls it and only exits when `goBack()` consumed nothing. |
| `tick(dt)` | Fixed-step safe — the soak steps it 1,800 times at 1/30 s. |
| `reportError(e)` | The single error path; `error-overlay` asserts it shows a readable message, records the error, and never throws itself. |

## Android shell

One Activity, one WebView. There are **two build paths**, because the two stores want different artifacts:

| Path | Script | Output | Toolchain |
|---|---|---|---|
| Sideload / device | `npm run build:apk` | `dist/bike-rider-<version>.apk` | `aapt2` → `javac` → `d8` → `zipalign` → `apksigner` (`tools/build-apk.mjs`) |
| AppGallery | `npm run build:aab` | `dist/BikeRider-<version>-<appId>.aab` | `gradlew bundleRelease` (`tools/build-aab.mjs`) |

The APK path is the offline one: the same pipeline Gradle wraps, minus a ~100 MB plugin download per machine,
which is what makes it work on a fresh checkout with no network. It links the **checked-in offline manifest**
`android/AndroidManifest.xml` and reads credentials from `android/keystore.properties`.

The AAB path is Gradle because **only the Android Gradle Plugin can produce a `.aab`**. It uses the module at
`android/app/`, whose manifest and `res/` are the shipped truth, and `android/app/build.gradle`'s
`signingConfigs.release`.

- **Gradle wrapper is pinned to 8.2.1.** Huawei's `com.huawei.agconnect` (AGCP) plugin fails on Gradle 9.x with
  `Cannot mutate the dependencies of configuration ':app:releaseCompileClasspath'`. Do not bump it without
  re-testing the bundle build.
- **App identity is `com.bikerider.game`** (renamed from `BikeRider.huawei` on 2026-10-21). It must match in
  `applicationId`, `namespace`, the `MainActivity` package, `agconnect-services.json`'s `package_name` and both
  manifests — and in the AppGallery AGC console, or `com.huawei.agconnect` fails the build.

- **No `INTERNET` permission.** The build is entirely local, so the manifest makes that structural: a URL changed
  by mistake in the web build cannot become a phone-home.
- **Assets are served over `https://appassets.androidplatform.net/`**, not `file://`. `shouldInterceptRequest`
  maps the path to `assets/public/…` and refuses anything off-host. `localStorage` — the whole save system — is
  unreliable on `file://`, and a service worker needs a real secure origin to register.
- **Text zoom pinned to 100** (`setTextZoom`): system font scaling breaks a canvas HUD with hard-coded pixel sizes.
- **`#050608` window and WebView background**, so no white frame shows between launch and first paint.
- minSdk 24, targetSdk 34, `sensorLandscape`, immersive sticky, keep-screen-on.
- Launcher icons are generated from code by `tools/make-icons.mjs` (five densities + round + API 26 adaptive).

## Deployment

**Web.** A static host over HTTPS (the service worker requires a secure origin), serving `public/` as-is. Bump
`VERSION` in `sw.js` on releases so clients evict stale caches — `index.html` is fetched network-first, so players
online always get the newest game. `npm run build:web` produces `dist/bike-rider-<version>.web.zip` plus
`dist/SHA256SUMS`. Serve at the SEO root **`https://alasarjadeed.com/`** — canonical, OG/Twitter and
`robots.txt`/`sitemap.xml` already resolve there.

**Android.** `npm run build:apk` produces `dist/bike-rider-<version>.apk`, signed with
`android/debug.keystore` (generated on first run) or `android/release.keystore` for `--release` — credentials come
from `android/keystore.properties` (gitignored). Install with `adb install -r dist/bike-rider-*.apk`.

**AppGallery.** `npm run build:aab` produces `dist/BikeRider-<version>-com.bikerider.game.aab` for upload
to the AppGallery Console. Both builds need a JDK 17 (`JAVA_HOME`); there is no `java` on `PATH` on this machine,
so the scripts look for `/home/oem/tools/jdk-17.0.20.1+1` as a fallback.

**Full pipeline.** `npm run build` runs sync → audit → regression → web → apk; `npm run release` additionally signs the APK. Neither builds the AAB — run `npm run build:aab` for the store bundle. `npm test` on its own is the gate
that should pass on every commit.

**What is not shipped.** Nothing extraneous — the old `public/music/` stems folder (unused sample
material) has been deleted. Both
builds print the excluded size rather than dropping it silently.
